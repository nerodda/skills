# Newsletter Writer

Turns source material into a complete, send-ready newsletter issue — sectioned and scannable, written for a reader deciding in seconds whether to keep reading an email, not for a search visit.

## When to use

Use this whenever a newsletter issue needs to be drafted, whether the source is a single long-form piece, a roundup of several items, or raw research notes. This is not "run [[long-form]] then shorten it" — the newsletter format has its own structural rules tuned for an inbox open, distinct from an article tuned for a search visit or standalone read. If the source material hasn't been gathered yet, [[researcher]] can pull it first. If the issue is meant to repackage one already-published long-form piece, confirm that's actually the goal — that's closer to what [[repurpose]] does for other channels, but the newsletter format itself is still drafted here.

## Inputs needed

Before drafting, confirm:
- **Source material** — the article(s), notes, links, or roundup items the issue draws from
- **Issue angle** — the one thing this issue is about, or the through-line tying a roundup together
- **Audience** — who's on this list and what they already know/expect from past issues
- **Section format** — this newsletter's established structure, if one exists (e.g., intro + 3 items + sign-off), so the issue matches past issues rather than inventing a new shape each time
- **CTA** — what the reader should do after reading, if anything

If there's no established section format yet, ask whether one exists before defaulting to a generic structure.

## Structural conventions

Write for a reader scanning on a phone who decides in the first few lines whether to keep going.

- **Subject line + preview text** — write both; the preview text should extend the subject line's promise, not repeat it.
- **Open** — one to three sentences, no throat-clearing, gets to why this issue matters right now.
- **Sectioned body** — break content into short, clearly labeled sections rather than continuous prose; each section should be skimmable on its own even if the reader skips the others.
- **Short paragraphs, short sentences** — inbox reading tolerates far less density than a web article. Cut anything that reads like it was pasted in from a longer piece without adaptation.
- **One CTA** — a single clear next action, not several competing links fighting for the click.
- **Sign-off** — close consistent with past issues (byline, P.S., etc.) if that convention exists.

## Output format

A complete newsletter issue: subject line, preview text, and full body in sectioned format, ready to load into the send tool. Note any source material that didn't fit and was cut, so nothing important is silently dropped.
